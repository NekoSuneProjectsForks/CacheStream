The native **Electron** desktop app is **merged into `main`** (now v1.14.2) — `main` is ahead of the old `feat/desktop-app` branch. It runs CacheStream without Docker on Linux x64/arm64 (incl. Raspberry Pi) + Windows x64/arm64, bundling Chromium + a static FFmpeg. README documents it at README.md:155-172.

Architecture (in `apps/desktop/`): Electron main (`src/main.js`) spawns the unmodified Next.js panel (`apps/web` standalone) via `utilityProcess.fork` (`web-server.js`), and `DesktopStreamer` (`desktop-streamer.js`) renders `/scene/*` through an offscreen GPU `BrowserWindow` (`setFrameRate`) → JPEG → bundled FFmpeg, exposing the SAME `127.0.0.1` control API (vendored `api.js`). H.264/AAC argv builders shared from `apps/streamer/src/ffmpeg.js`. Cross-platform audio: `AUDIO_TRANSPORT=fifo|tcp` env (default `fifo` = Docker unchanged); desktop uses `tcp` with a loopback `AudioRelay` (`audio-relay.js`). Web side honors it: config.ts:144 + music.ts:65. CI: `.github/workflows/desktop.yml` builds 4 targets.

**v1.14.2+ (this session): RTMP ingest + LAN binding added to desktop.** The third Docker service (`ingest`/nginx-rtmp) is now embedded in the desktop app via `apps/desktop/src/ingest.js` — `node-media-server` (pure JS, in asar) receives RTMP, bundled FFmpeg remuxes to flat HLS in `<userData>/hls/`, and a tiny Node http server mirrors nginx-rtmp's surface (`/hls/<key>.m3u8`, `/stat` XML synthesized from sessions, `/health`). Web app made Docker-compatible: new `config.ingest.httpUrl` from `INGEST_HTTP_URL` (default `http://ingest:8080`) replaces 4 hardcoded `ingest:8080` refs (status x2, playlist, keys routes). Panel + RTMP now bind 0.0.0.0 (LAN/phone/OBS reachable); `preferredPort()` keeps 7788/1935 when free else random; `lanAddress()` → `RTMP_PUBLIC_HOST`; tray shows LAN URLs. main.js wires/stops IngestServer. Verified: all desktop JS parses, NMS 2.7.4 API matches (postPublish/donePublish, session.socket/videoWidth/videoCodecName). NOT yet run: full `next build` + live OBS→Twitch test.

**v1.14.2+ (this session): `npm run dev` now boots clean on Windows — verified.** Fixed three dev-pipeline bugs that previously blocked launch: (1) **space-in-path** — build scripts ran with shell:true and Node didn't quote args, so `…\Forked Projects\…` split; added `runSafe()` quoting in `scripts/native.mjs` (used by build-web + ensure-web). (2) **better-sqlite3 ABI** — Next.js standalone tracer STRIPS the native module's build sources (binding.gyp/src/deps) from build/web, so `electron-rebuild -m build/web` silently no-op'd and the panel crashed at boot with NODE_MODULE_VERSION 127≠130. Fix in `scripts/native.mjs` `rebuildSqlite()`: restore full module from `apps/web/node_modules/better-sqlite3` into the stage, electron-rebuild `-v <electronVer> -o better-sqlite3 -f` (falls back to `--build-from-source`), then VERIFY by loading it under `electron.exe` with `ELECTRON_RUN_AS_NODE=1` before stamping `build/web/.electron-version`. `ensure-web.mjs` calls `sqliteNeedsRebuild()` (checks marker AND that it actually loads) so `npm run dev` self-heals ABI without a full next build. (3) sandbox-only: my Bash shell had `ELECTRON_RUN_AS_NODE=1` set (makes `electron .` run as plain Node → `app` undefined at main.js:26) — NOT a real bug; unset it to launch the GUI. Also: orphaned electron.exe hold the single-instance lock → kill by path (`Get-Process electron | ? Path -like '*CacheStream*'`) between runs. **Verified live:** panel /api/health 200, embedded ingest /health=ok + /stat valid XML, /api/ingest/status returns pushUrl rtmp://<lanIp>:1935/live with lastError null, DB seeded 9 scene presets (sqlite writable). Still NOT tested: actual OBS→HLS→Twitch live push (needs encoder + stream key).

**Twitch OAuth over http (no HTTPS):** desktop app now serves the panel from `http://localhost:7788` (was `http://127.0.0.1`). Twitch allows http OAuth redirects ONLY for the literal host `localhost`, not the IP form — that's the whole fix, no TLS/tunnel needed. main.js uses `panelOrigin = http://localhost:${webPort}` for PUBLIC_URL, DEFAULT_SCENE_URL, the window, and the logged url; STREAMER_URL/INGEST_HTTP_URL/ingest httpHost stay 127.0.0.1 (internal). Cookies already drop `Secure` when TRUST_PROXY=false (apps/web/src/lib/cookies.ts:60), which the desktop sets — so http cookies work. Dev-app redirect URL to register: `http://localhost:7788/api/auth/twitch/callback`. Verified: login route emits redirect_uri=http://localhost:7788/api/auth/twitch/callback. Caveat: if 7788 is taken, preferredPort falls back to random and the redirect URL changes (won't match registered) — normally 7788 is free.

**Scene URL both-sides fix + shipped (commit 5a7f1e0 on main, 2026-06-21):** the built-in scene presets were hardcoded `http://web:7788` (Docker compose host) which the desktop streamer can't resolve. Fix: `config.scene.baseUrl` from `SCENE_BASE_URL` (default `http://web:7788`; desktop sets localhost), `toStreamerUrl()` in streamer-client.ts rewrites any self-host (web/localhost/127.0.0.1/0.0.0.0/PUBLIC_URL host) scene+overlay URL to that base at the streamer choke point, and boot.ts migrates+dedupes existing presets by path (added `store.updateSceneUrl`). User confirmed working and it's committed+pushed. `npm run dev` verified booting clean on Windows. Confirmed by user as working end-to-end.
